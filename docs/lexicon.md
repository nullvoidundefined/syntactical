## Domain vocabulary

One line per domain noun used across this codebase's naming (files, functions, variables, data keys). `language` and `difficulty` are not listed separately: each is already a single, unambiguous identifier (`LANGUAGES`/`language`, `DIFFICULTIES`/`difficulty` in `appConfig.js`) with no competing name anywhere in the code, so there is nothing to settle for them. Do not introduce synonyms for either (`track`, `tier`, `level`, `subject`) as new identifiers.

- bank - the array of question objects for one language and difficulty pair, stored as `content/<language>/<difficulty>.json` and loaded through `useQuestionBank` - chosen over: `deck`, `pool`, `set` because the original data module named it `getQuestionBank`, and the content files, the manifest's `banks` map, and `useQuestionBank` kept the noun.
- round - one full pass through a shuffled question bank, from the first question to the results screen - chosen over: `session`, `attempt` because `QuizRound`/`useQuizEngine`'s `isComplete` and `ResultsScreen`'s "Retry" already model one bank traversal as a single unit, named this way in `components/quiz/QuizRound.tsx`.
- query - the per-card explanation of the syntax/method/context behind a question's example, stored on each question object as `question.query` (`{title, syntax, explanation, tags}`) and surfaced through `QueryDrawer` - chosen over: `explanation`, `reference` because the user's original spec named this feature "Query" directly (see `docs/original-prompt.md`, requirement 4), and `components/query/QueryDrawer.tsx` and the "Query" button in `components/quiz/QuestionCardFrame.tsx` already use the term.
- question - one item in a bank: a single multiple-choice (`type: 'mc'`) or boolean (`type: 'bool'`) card, identified by `id` (e.g. `py-med-01`) - chosen over: `card`, `item` because `question.prompt`, `question.type`, `question.query`, and `useQuizEngine`'s `currentQuestion` already use this noun for the data object; `Card` is reserved for the React component that renders one.
- code block - the rendered, Prism-tokenized snippet of `question.code` or `query.syntax` rendered as nested `Text` runs by the shared `CodeBlock` component - chosen over: `snippet`, `syntax highlighter` because `question.code` and `query.syntax` are the existing field names it renders, and `components/quiz/CodeBlock.tsx` is the only file name it needed to match.
- manifest - the fetched `manifest.json` that lists every language, its display fields, its highlighting grammar, and the bank file and bank hash for each of its difficulties - chosen over: `catalog`, `index`, because `index` already named the original data module and `catalog` suggests something purchasable.
- bank hash - the SHA-256 of a bank file's bytes, written into the manifest at build time, compared against the cached bank's hash to decide whether to download, and checked against the downloaded bytes before they are accepted - chosen over: `version`, `etag`, because it is computed rather than maintained by hand, and it is manifest data rather than an HTTP header.
- bundled bank - the copy of a bank shipped inside the app build, used when no cached bank exists - chosen over: `default bank`, `seed`, because `seed` implies a database.
- cached bank - the last verified bank downloaded at runtime and stored on the device, stored together with its bank hash as one entry - chosen over: `stored bank`, `local bank`.
- content base URL - the absolute URL the manifest and banks are fetched from, configured as `CONTENT_BASE_URL` - chosen over: `api url`, because there is no API.
- grammar - the Prism language id used to highlight a language's code blocks, named per language in the manifest - chosen over: `syntax`, because `query.syntax` already names a question field.
- download indicator - the subtle status element shown while a bank is transferring - chosen over: `spinner`, `loader`, because it names what is happening rather than how it looks.
