# Launch placeholders

The API can deploy before every secret and setting exists. With `ALLOW_STUBBED_INTEGRATIONS=true` on the Railway service, a missing integration is replaced by a stub that fails closed (owner decision 2026-10-04). Without that variable the server still refuses to start on a missing required variable. This page lists everything that is stubbed or a placeholder and must be replaced before the app is fully runnable. A stubbed deploy is visible: the boot log has one `running with stubbed integrations` line and `GET /health/ready` returns `"stubbed": [...]` with the names. When nothing is stubbed the field is absent.

Remove `ALLOW_STUBBED_INTEGRATIONS` once every server row below is real. With it gone, a variable that goes missing later stops the deploy instead of silently stubbing.

## Why each stub fails closed

- No email provider: no email is sent, so no code leaves the server and nobody can sign in. Nothing sensitive is logged.
- No webhook credential: the route is closed (503), never open. An unauthenticated webhook cannot be accepted or recorded.
- No rate limit secret: a random per-boot value, never logged, so counters cannot be forged from a known value.
- No allowed origins: no browser origin passes CORS or the CSRF origin check.
- `DATABASE_URL` and `PAID_CONTENT_DIR` are never stubbed.
