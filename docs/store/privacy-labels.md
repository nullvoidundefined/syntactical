## Facts the answers rest on

- **Location.** The app requests no location and sends none of its own. On iPhone and Android, Google AdMob receives the device's IP address with each ad request and may infer an approximate location from it; the AdMob rows below declare it. PostHog is created with `disableGeoip: true`. The timezone is an IANA zone name such as `America/Chicago`, stored so the server can compute the user's day boundaries. It is not a location. Treat it as "Other user content/data" only if a reviewer asks.
- **Analytics identity.** `persistence: 'memory'` means no cookie, local storage, or AsyncStorage key is written. A guest gets a fresh anonymous id each launch; after sign-in events carry the server user id, never the email. Event properties named `email`, `code`, or `token` are rejected by `findProblem`.
- **No tracking.** Nothing is combined with data from other companies' apps or sites for advertising, and no data is shared with data brokers. The app does not show the App Tracking Transparency prompt and does not need to.
- **Sponsored cards on the web and from direct sponsors.** The house card and a direct sponsor (`content/sponsor.json`, with its icon under `content/`) are served from our own content host; the sponsor receives nothing unless the user opens its https link. On the website, the EthicalAds client (`media.ethicalads.io`, loaded only when `ETHICALADS_PUBLISHER` is set, and only by a sponsored card shown to a user who is not Pro, so a Pro user's browser never contacts EthicalAds) sets no cookies and needs no consent banner; the browser's requests to it carry the IP address, as any request does. Card views and presses are the `ad_shown` and `ad_clicked` events above.
- **AdMob cards.** AdMob requests are always non-personalised, so the app never shows the App Tracking Transparency prompt and nothing is "used for tracking". In the EEA and UK the UMP consent form runs before the first request; the SDK initialises whether consent is given or declined. Owner check, before every submission: read Google's current data disclosure for the Mobile Ads SDK (the Apple App Privacy page and the Play Data safety page) for the SDK version in `package.json`, and confirm every data type it lists against the rows below, not only Device ID. Each row marked "confirm" stays marked until that check; add a row for any type the disclosure lists that is not here.
- **Passwords.** Optional. The only stored form is a salted scrypt hash in `users.password_hash`; the password is never kept on the device and never logged. At sign-up and password change the server sends only the first 5 hex characters of the password's SHA-1 to Have I Been Pwned (k-anonymity, padded responses) to check for breaches, so neither the password nor its full hash leaves the server. The hash is deleted with the account.
- **Sessions.** Only a SHA-256 hash of the session token is stored (`sessions` table). A native client keeps the token in the device keychain or keystore (`expo-secure-store`); the web client uses a cookie.
- **Encryption.** Traffic uses HTTPS only (`API_BASE_URL` must be `https://`).
- **Deletion.** In the app: Settings, Delete account, type DELETE, confirm (`components/auth/DeleteAccountDialog.tsx`, `DELETE /v1/me`). It removes the password hash (it lives on the user row), sessions, answer events, daily progress, goal changes, and the email's one-time codes and rate-limit counters in one transaction (B-59). Entitlement and purchase event rows stay with `user_id` cleared for accounting, and hold no email or name. Signing in again with the same email creates a new, empty account. In-app deletion does not reach vendors: PostHog events identified by the user UUID, the RevenueCat customer record, and Resend's send log remain with those vendors, Google AdMob's records of the sponsored cards it served to the device remain with Google (not tied to the account), and store transactions remain with Apple and Google.
- **Owner check, PostHog.** `disableGeoip` stops location lookup, but PostHog still receives the request IP. In the PostHog project settings, turn on "Discard client IP data" so the IP is not stored, and then the "no location" answers below hold.

## Content rating and other forms

- Play content rating questionnaire: no violence, no sexual content, no gambling, no user-to-user communication, no location sharing. Expected result: Everyone.
- Play "Ads": yes. Free users see sponsored cards (AdMob native ads on Android, non-personalised; a named direct sponsor; or a card for Syntactical Pro); Pro removes them.
- Play target audience: 18 and over is the safe choice. The content is programming practice questions, and the app is not designed for children. Choose the audience to match the owner's intent; picking under 13 triggers the Families policy.
- Apple export compliance: the app uses only HTTPS through the platform, which qualifies for the exemption. Answer "No" to non-exempt encryption in the build questions. To skip the prompt on every build, the owner may add `ios.config.usesNonExemptEncryption: false` to `app.config.ts` after confirming this answer.
