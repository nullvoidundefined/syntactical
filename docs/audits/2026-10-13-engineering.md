## Two findings that are not cleanup

These two came out of the audit but are defects, not refactors. They are listed first because they change what a user sees.

**1. Production and preview builds point at hostnames that do not resolve.** `app.config.ts:7` defaults `DEFAULT_API_BASE_URL` to `https://api.syntactical.dev/v1/`; `eas.json` lines 14 and 21 set the preview and production `API_BASE_URL` to `staging-api.syntactical.dev` and `api.syntactical.dev`. Neither name has a DNS record (checked with `dig` from this machine on 2026-10-13). `server/DEPLOY.md:56` and `:110` already say the Cloudflare CNAME does not exist and name the Railway host to use, `api-production-9973.up.railway.app`. `docs/session-handoff/session-handoff.md` says the opposite, that both hosts are live. The device-checklist runs on 2026-10-06 and 2026-10-08 list sign-in as blocked, which is consistent with the app calling a dead host. Owner action: either create the two CNAMEs on Cloudflare per the runbook, or change the three defaults to the Railway hostnames until the records exist. Evidence: cross-cutting report, D1.

**2. `pipeline review` never lists topic-track cards.** `pipeline/src/commands/review.ts:78` scopes the `backend-security` and `frontend-security` tracks to `disputed` items, and `buildReviewItems.ts:72` skips everything else. Nothing has written a `disputed/` file since PR #115 (2026-10-05) replaced the judged gap-fill with batch generation, so the review file for those tracks is always empty and generated cards for them never reach the owner through the review command. Confidence is high from reading; the pipeline audit asks that it be confirmed by running `pipeline review` against a staged topic bank. Fix is small. Evidence: pipeline report, finding 2.

## Decisions for the owner

1. **DNS.** Create the `api` and `staging-api` CNAMEs on Cloudflare per `server/DEPLOY.md`, or retarget `app.config.ts:7` and `eas.json` at the Railway hostnames. Nothing else in this audit matters to a user until the app can reach the API.
2. **Judged route.** Delete (default) or keep as an unwired library. Keeping it means every future refactor pays to keep roughly 6k lines compiling and green.
3. **60% coverage rule.** It is in the shared conventions and enforced nowhere (no `coverageThreshold` in `jest.config.js`, no `coverage` block in any vitest config). Enforce it, or write the override into the project `CLAUDE.md`.
4. **Lint and Prettier as gates.** 53 oxlint warnings pass CI and 341 files fail `prettier --check` under the "format only what you touch" policy. One formatting commit plus `.git-blame-ignore-revs`, then `--deny-warnings`, or leave both advisory.
5. **Workspace pruning.** 28 git worktrees, 279 local branches of which 141 are merged into `origin/main`, 163 remote branches, and the main checkout on `feat/javascript-path`. This is a cleanup plan for the owner, not a command for an agent: unlock and `git worktree prune`, `git branch -d` the merged set, enable "Automatically delete head branches" on GitHub, and return the main checkout to `main`.
